A CSS framework where every element occupies an integer number of character cells. Borders are box-drawing glyphs, not 1px rules; spacing is in cells, not rem; and hierarchy comes from bold, dim, inverse and color — never from a font-size change.

Think “Bootstrap, but the layout engine is a character grid.”

Every page of this site is built with the framework it documents, and every one of them is measured: test/docs.spec.js reads the bounding box of each element here and fails if a width is not a whole number of ch, a height not a whole number of lh, or an edge not on a cell boundary. The listing under the example above was generated from the live markup directly above it, so it cannot drift.

This is not a skin

Terminal stylesheets already exist. They set a monospace font and a dark palette, but their borders are border: 1px and their spacing is in rem, so nothing lands on a character boundary and the illusion breaks as soon as you look closely — or zoom in, or change the font size.

Here the grid itself is character-faithful. One cell is 1ch wide and 1lh tall, every horizontal length is Nch and every vertical length Nlh, and the screen container rounds its own width down to a whole column count. Resize the window and the page snaps. The number in the status bar is this page's size in cells.

Quick start

Two stylesheets and one class on <html>. No build step, no dependencies, no JavaScript.

<!doctype html>
<html lang="en" class="font-jetbrains-mono">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<link rel="stylesheet"
      href="https://cdn.jsdelivr.net/gh/kent-orr/webterm@main/fonts/webterm-fonts.css">
<link rel="stylesheet"
      href="https://cdn.jsdelivr.net/gh/kent-orr/webterm@main/src/webterm.css">
</head>
<body>
  <div class="screen">
    <h1>webterm</h1>
    <p class="mt-1">Every element here is a whole number of cells.</p>
  </div>
</body>
</html>

That is a complete page. webterm.css imports the ten grid files and the default theme, Pawpaw, so it paints without a theme <link>. The font stylesheet is separate because the bundled fonts are the one heavy thing in the repo and a page that already ships a monospace font does not need them — but it does need a calibrated one, or the row height drifts from the glyph box.

@main is a moving target that jsDelivr caches for half a day at the edge, so pin a tag or self-host for anything real.

The rules

Eight constraints, and every component in the framework satisfies all of them. They are the whole design.

  1. One cell is 1ch × 1lh. All horizontal lengths are Nch, all vertical lengths Nlh. No px, rem, em or % inside the screen.
  2. One font, one size, one line-height for the entire document. Never changed per element.
  3. Hierarchy comes only from bold, dim, inverse video, underline, color, whitespace and uppercase. No size changes.
  4. Borders are glyphs, never CSS border with px widths.
  5. Unicode box-drawing is the default; an ASCII-only border style is provided as an option.
  6. No raster images in the core.
  7. Wide glyphs — CJK, emoji — are out of scope for v1.
  8. Breakpoints are expressed in columns, not pixels.

Rule 3 is the one that surprises people, so here is the entire type scale. There is no second font size anywhere in the framework.

Four layers

grid
The core. Cells, boxes, type, tables, forms, components. CSS only, names no color.
theme
Sixteen ANSI slots plus a handful of semantic aliases. Sets nothing but color. Nine themes ship; Pawpaw is the default.
skin
Optional. The .crt glass — scanlines, glow, vignette, a blinking cursor — under one rule: it declares nothing that can move an element.
behavior
Optional. Toasts, loading states, placeholders, modals, collapse, tabs, dropdowns, tooltips, offcanvas. The CSS never depends on it, so each one has a static form that renders with no script loaded.

Each layer's rule is a measurable one, and the test suite measures it. That is the difference between a framework and a stylesheet with opinions.
