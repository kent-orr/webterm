Behavior

Everything on the other pages is CSS. This is the one optional ES module, and it adds what a page usually needs a framework for — loading states, placeholders, toasts, modals, collapse, tabs, dropdowns, tooltips and drawers — with no build step and no dependency.

<script type="module" src="src/behavior/webterm.js"></script>

It sets window.Webterm, so the data attributes below work whether or not you write any JavaScript yourself. This page loads it, which is why the examples here are live.

The CSS never depends on the JS

Every component here has a complete static form that renders with no script loaded; the module only drives transitions between states. A page whose module fails to load degrades to static boxes rather than invisible ones — and the test suite loads this whole page a second time with JavaScript disabled and measures it again, which is the only way that claim stays true.

Collapse, dropdowns and tooltips do better than degrade: with no script at all they still work, because a disclosure is a <details> and a tooltip is an ::after.

Two conventions run through all of it. Everything that is not a class is namespaced — attributes are data-wt-*, events are wt:component:verb with the before-events cancelable. And motion is cell-stepped: a terminal does not tween, so every animation advances a whole cell or a whole row on --wt-tick, 60ms, and prefers-reduced-motion means the final state immediately rather than a faster animation.

Loading

Spinners and the indeterminate bar animate in CSS and need no script at all, which is the point: a spinner driven by JavaScript stops spinning exactly when the main thread is busy, which is the one moment it is there to cover.

There is deliberately no braille spinner. It is what every terminal tool uses, and it is 12px wide in a 10px cell in two of the three bundled fonts. A frame set may use ASCII and U+2500–259F, which is the range the bundled fonts cover in full, and the spec measures every frame against 1ch in each font.

A loading state hides its content rather than removing it, so nothing resizes while it waits. Webterm.setLoading(el, true) does that to any element, wrapping the children it should hide and leaving a box's edge and title alone.

Placeholders

The component that is new rather than ported. A placeholder is locked to the cell count of the real text, and the value arrives by settling into it: every cell shows a random character until its turn, then takes its real one and keeps it.

Because the width is the real string's width from the first frame, resolution causes no layout shift at all. That is what a character grid can promise and a rem-based skeleton cannot. Whitespace never scrambles — the shape of a value, how many words and how long, is most of what a reader is waiting for.

Three states make it useful rather than decorative: Webterm.ph(el).hold() while a fetch is in flight, .resolve(text) on a value that may differ from the authored one, and .fail(). The declared cell count outlives the animation, so resolving onto longer text clips rather than moving the page.

.ph-area is the same settle in two dimensions, over content that is already on the grid. With no script the mask is a flat ░ skeleton.

Toasts

A toast is a .box in a stack pinned to a corner, so it inherits the border, the title and the semantic tints. The stack is created on first use, or written by hand.

The bottom border is the countdown. A cell at a time, from the right, the ─ run turns to ░ until the whole edge is shaded and the toast goes with it. The message types in, and the box does not move while it does: the tail that has not arrived is laid out but hidden, so the wrapping never changes.

Hovering holds the timer. Webterm.config.toastMax bounds how many are visible and the rest queue, and an identical consecutive message is counted as ×N on the existing toast rather than stacked. The timeout is time, not motion, so reduced motion does not collapse it — only the typing stops.

Modals

A native <dialog> that is also a box, so the focus trap, Escape, the inert background and the top-layer stacking are the browser's work.

The dim behind it is not a translucent black. The grid layer names no color, so it is a run of block-shade glyphs painted in --bg, dithering the page the way a TUI does. The dialog is centered on a whole cell and hangs from --wt-dialog-top, because centering something whose height CSS does not know cannot be snapped to a row.

Opening a modal locks page scroll without changing the column count, which is the one thing a character grid has to get right here: the reset reserves the scrollbar gutter permanently, so a scrollbar appearing and disappearing never re-rounds the screen and reflows the page behind the dialog.

And because a terminal interface asks small questions constantly, there are two promises for the common cases:

if (await Webterm.confirm('Drop replica charlie?')) drop()
const host = await Webterm.prompt({ label: 'host', fieldCells: 24 })

Collapse

A <details>, so it opens and closes with no script. What the module adds is the animation, and it is the vertical half of the placeholder's promise: the body's height steps a whole row at a time on the tick, so the page below it is never mid-row.

The row count comes from measuring the content and the tick count from data-wt-duration, so a twenty-row region opens in the same time as a two-row one. A shared name makes the browser close the sibling — an accordion, free.

The marker is + and - rather than ▸ and ▾: those live in Geometric Shapes, outside the range that measures a single cell in all three bundled fonts.

Tabs

With no script a tab set is a document with two sections and two links to them: every panel readable, nothing hidden. The module makes it a tablist with roving focus, arrow keys and one panel at a time.

The reason tabs are here at all is the height lock. Panels are different heights, so switching them moves everything below — the layout shift this framework exists to avoid, one axis over. .tabs-panels is measured across every panel and pinned to the tallest in whole rows, and re-measured when the window changes, since text rewraps. There is no transition: a terminal repaints a pane.

Dropdown

The same disclosure, floating. Every position the menu can take is anchored to an edge of the trigger, so it sits directly against a trigger of any height, and flipping near a viewport edge means anchoring to the opposite edge rather than nudging by a measured distance. Nothing can land mid-cell, because nothing computes a position.

The module adds what a native <details> has no opinion about: Escape, a click outside, one open at a time, roving focus through the items, and focus handed back to the trigger on close.

Tooltip

An inverse strip against the trigger's edge, up to --cells wide and wrapped to whole rows. No arrow: a CSS triangle is a sub-cell shape, and the glyph that would stand in for one is not single-cell in every bundled font, so the bubble sits flush — which is what a TUI hint does.

With no script the whole component is .tip::after, taking its text from the attribute on hover and focus. With the module it is a real element instead — a pseudo-element cannot be the target of aria-describedby and cannot be flipped away from a viewport edge — and the static one is stood down so only one ever shows.

Put .tip on something focusable, or give it tabindex="0": a hover-only tooltip is not reachable from the keyboard.

Offcanvas

A drawer is the modal's <dialog> anchored to an edge, so it inherits Escape, the focus trap, the inert page, the top layer and the scroll lock. It slides a whole number of cells per tick.

The dim behind it is a sibling rather than a child of the dialog, because a transform makes a dialog the containing block for its fixed descendants — a child dim would slide with the panel it is meant to sit behind.
