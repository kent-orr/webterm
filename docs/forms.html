Forms

Every control is text. A button is its label plus four cells for the brackets, a checkbox is three cells, a field is as many cells as you ask for — so nothing here needs a measured size, and nothing here can be half a cell wide. Focus is inverse video, never an outline ring: an outline is a sub-cell box drawn in px, which is rule 1 and rule 4 at once.

Buttons

The brackets are generated content, so [ OK ] is exactly six cells and the label inside is exactly what you typed. Hover and focus invert the whole run, brackets included, which is what a terminal does to a selected item.

Text fields

A field is a dim fill N cells wide with a block caret, in the widths the layout classes offer: .field-8, -12, -16, -24, -32 and .field-full. The default is 20 cells.

The caret is a block, because a 1px I-beam in a character grid is the same category error as a 1px border. A focused field takes the theme's selection pair rather than a highlight of its own.

A <textarea> is the one control whose height is a row count rather than a cell count, and rows already says it in rows — so it needs nothing from the framework but the fill and the caret. It does not resize: a drag handle sets a px height.

Checkboxes, radios and selects

The native controls are replaced by their glyphs — [x], [ ], (•), ( ) — and keep every behavior the browser gives them, including the label click target and the keyboard.

The wrapper is what carries the width and the ▾; the <select> inside it is a real select, so the dropdown it opens is the operating system's. That one is not on the grid and cannot be — it is not drawn by the page. If you need a menu that is, use the box-drawn dropdown in the behavior layer.

Form rows

.form-row is a label column of 16 cells and a control column that takes the rest, with the one-cell gutter rows use everywhere else.
