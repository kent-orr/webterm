Type and tables

Rule 2 says one font, one size, one line-height for the whole document, and rule 3 says hierarchy comes from somewhere else. Between them they delete the entire conventional toolkit: no scale, no leading, no weight ramp beyond the two the font has, no indents.

What is left is the terminal's own toolkit — bold, dim, inverse, underline, color, uppercase and blank rows — and it turns out to be enough, because it is what every TUI has ever had.

Headings

No class needed. The reset and type.css restyle plain HTML: an h1 is an inverse strip, h2 and h3 get a rule on the row below, h4 to h6 are bold, dim and uppercase in turn. Every one of them is the same size.

The rules under h2 and h3 are glyph runs clipped to the heading's width, which is why they stop where the text block ends rather than where the words do.

Color

Sixteen ANSI slots, named .c0 to .c15, plus five semantic aliases that point into them. Use the aliases: a theme is free to put any color in any slot, and .c1 is only red by convention.

Prose

List markers live in their own cells, so a wrapped line hangs under the text instead of under the bullet. An ordered list reserves four cells and right-aligns the number, which keeps two- and three-digit items aligned with each other.

Tables

Give column widths in ch with a <colgroup>. The table is table-layout: fixed, so without them auto layout distributes leftover space in fractions of a pixel and puts every column after the first off the grid. This is the single most common way to break the illusion, and it is also the easiest to fix.

The separators are │ glyphs drawn in the padding cell they own, and the header rule is a ─ run with ┼ at each crossing. Where a separator meets the rule the crossing wins, so the dash run stops one cell short of it — that detail is why the header reserves a blank row underneath itself.

.num right-aligns a column, .table-zebra stripes alternate rows, and a table pairs well with .box-tight, which drops the gutter the table's own padding already provides.
