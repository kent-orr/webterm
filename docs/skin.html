The skin

Layer 3, optional and additive: a CRT glass over the page. One more <link> and one class on <html>.

This page has it on. Scanlines, phosphor glow and a corner vignette are between you and every word here. Turn them off and compare — nothing on the page will move, which is the whole claim.

One rule

The skin declares nothing that can move an element.

Not “should not” — it is measurable, and test/skin.spec.js measures it twice. Every rect on the kitchen-sink page is identical with .crt and without it, and a page that loads crt.css but never applies the class is pixel-identical to one that does not load it at all.

The first holds the promise. The second is what makes a skin something a page can ship unconditionally and switch on at runtime — which is exactly what the switch above does.

On a real element the layer sets text-shadow, an animation and custom properties, and nothing else. Everything it paints is on a fixed pseudo-element. Every selector names a skin class. Those three facts are what make the rule structural rather than lucky, and a source lint checks all three.

This page is the demonstration: it is swept by the same suite as every other page here — integer cells, cell boundaries, continuous box borders — and it is swept with the glass on.

No px in it either

A scanline is a sub-cell shape, which looks like the one place the framework would have to reach for a pixel. It does not. The period is 1lh and the ink band is a fraction of 1lh, so there is one scanline per character row by construction, and the glow radius is in ch. The effect scales with the font instead of drifting away from it.

That is also the webterm-specific part of the effect. A CRT skin elsewhere picks a 2px or 4px period because it has no better unit available; here the row is the unit, and the lines land on the same boundaries the text does.

Why the ink is the background

The theme contract has no darker token to reach for. --c0 looks like one — a scanline is the absence of phosphor, so it should ink in the theme's black — and it is wrong. The ANSI slots are a palette, not a brightness order: solarized-light sets --c0 to a light tone, because that is what slot 0 of the light Solarized palette is. A --c0 overlay would lighten that theme.

--bg darkens a dark theme, does nothing to a light one, and never inverts. Set --wt-crt-ink: var(--fg) if you want one on a light theme anyway.

The glow is currentColor, so a green span glows green and a red one glows red.

The cursor

.cursor-blink adds the animation and nothing else. The lit cell is .inverse from the grid layer, so a page that leaves the skin out keeps a steady block cursor rather than losing it.

It blinks on the framework's one clock: eight ticks lit, eight clear, 480ms each at the default tick. The step function is steps(2, jump-none), so it is on and off rather than a fade — a terminal cursor does not fade. Under prefers-reduced-motion or data-wt-motion="off" it parks lit.
